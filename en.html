This page answers three questions: how the repo calls the LLM today, which models belong on the ladder and why they suit Vietnamese legal question answering, and what the ladder does when a model runs out of quota.

Read from codedevelop · 3d64c4d

    Key points

    • The old way uses one fixed model from LLM_PROVIDER and LLM_MODEL. A 429, a 5xx or a timeout fails the request at once: there is no fallback to another model, and nothing remembers which model ran out of quota.
    • The ladder should be one LLMProvider wrapping several adapters, so LLMService, answer.py and the citation check need no change.

    Choosing models · real Vietnamese scores

    Which models are good enough at Vietnamese

    SEA-HELM, Vietnamese table · updated 2026-09-18

    Each row is the model's real score on the Vietnamese part of SEA-HELM, the benchmark AI Singapore runs for Southeast Asian languages. Drag the thresholds to see which models drop out. Models that pass are ranked by total score, and the ladder takes up to 4 rungs. Each provider may hold only a limited number of rungs, so that when one provider runs out of quota or goes down there is still a fallback.

    Ladder:

    Total = 0.4 × Vietnamese + 0.3 × Knowledge + 0.2 × NLR + 0.1 × Instruction Following. Knowledge and reasoning weigh more because legal questions need the right concepts and the ability to work out conditions and exceptions. Where a model has both a reasoning and a plain variant, the page uses the higher score, which is the variant with thinking on. Names follow SEA-HELM; check each provider's real model ID before putting it in the config.

    Key points

    • With the default thresholds the ladder is Gemini 3.8 Flash → Gemini 3.5 Flash → GPT 5.6 Sol → Qwen 3.5 397B. All three providers already have an adapter in the repo (gemini, openai, qwen), so no new adapter is needed.
    • Mistral, Haiku 4.5, GPT OSS and Llama 4 sit 6 to 18 Vietnamese points below the top group and are dropped. Mistral is a rung on the ai-ladder, so that rung goes when porting to this repo.
    • Gemini 3.1 Flash Lite actually scores 75.24. It is dropped only by the owner's "no lite models" rule, not for weak Vietnamese.

    Evidence specific to Vietnamese law

    Good Vietnamese does not mean remembering the law

    VLegal-Bench (arXiv 2512.14554, Dec 2025) · Accuracy, %

    SEA-HELM measures general Vietnamese only. For evidence about law, this uses VLegal-Bench, a Vietnamese civil-law benchmark of more than 10,000 expert-labelled samples. It has only scored the previous generation, but that is the previous generation of the very model families chosen above. Pick a task to compare.

    Real data from the paperPrevious-generation models

    Key points

    • Large general API models (GPT-4o, Gemini 2.5 Flash) trail a model fine-tuned for law by only a few points, while small or old models fall far behind. That is why the ladder keeps only large Gemini, GPT and Qwen models, and drops PhoGPT and Qwen2.5-7B from the repo's original proposal.
    • On Legal Schema Recall every model scores about 22–27%, close to guessing. No model reliably remembers how the law is structured, so the pipeline must put the exact clauses into the context and check citations, as the repo already does.
    • VLQA (Jul 2025) finds that models still often make things up on legal questions. The project's own 20-question eval remains the final gate before the ladder is switched on.

    Reasons for each rung

    Why these four models suit Vietnamese legal Q&A

    1. Gemini 3.8 Flash. Vietnamese 78.40, the best of the Flash group and only about 0.3 below Opus 4.8 and Gemini 3.1 Pro. Knowledge 91.88, second on the whole table, which matters because legal questions turn on exact terms. Its predecessor, Gemini 2.5 Flash, scored 81.4% on article recall in VLegal-Bench. The repo already has a Gemini adapter.
    2. Gemini 3.5 Flash. Vietnamese 77.80, Knowledge 91.68, nearly level with rung 1. Same provider as rung 1, but Gemini counts quota per model, so it still works when 3.8 Flash runs out for the day.
    3. GPT 5.6 Sol. Vietnamese 77.06, Knowledge 89.36, and Instruction Following 95.32, so it sticks closely to a format. That matters because the output must be JSON that fits the contract, with valid citations. It is the first rung at another provider, so the ladder still has a path when Google is down. Its predecessor, GPT-4o, led the general models on VLegal-Bench. The repo already has an OpenAI adapter.
    4. Qwen 3.5 397B. Vietnamese 78.15 and Instruction Following 96.24, the highest of the four rungs. Called through the DashScope API with the existing Qwen adapter. It is also an open-weights model, so it can be self-hosted later if data must stay in-house.

    Not chosen, and why

    • GPT-4o, the model proposed in llm-proposal.md, is an older generation and no longer on the current SEA-HELM table. Replace it with a newer GPT model that has a measured Vietnamese score.
    • PhoGPT 7B5 scores only 24.0 and Qwen2.5-7B 57.5 on VMLU, far below the chosen group.
    • Gemini 2.5 Pro and Gemini 3 Flash preview on the ai-ladder have no score on the current SEA-HELM table, so they cannot be verified. Add them only after the project eval has run on them.
    • The flagship group (Opus 4.8, Gemini 3.1 Pro, GPT 6 Astra) is less than 0.3 Vietnamese points above Gemini 3.8 Flash. They are likely to cost more and run slower, which makes the 30-second budget hard to meet. Check real prices and latency before switching that option on.

    What the ladder does when a model runs out

    Ladder from the model section above · 30-second LLM budget (llm-proposal.md)

    Set each rung's state and press Next to watch the request move down. Then press Next request to see what the quota store remembers: a rung that ran out is not called again, and a rung with 3 bad outputs is demoted.

    Simulated with the proposed rulesLatency is assumed

    Latency in the simulation is assumed by model group (Flash about 5 seconds, others 8–14 seconds). Replace it with measured p50 and p95 when the eval runs.

    Key points

    • Keep Team 3's spec: a bad output is not retried, not even on another rung. It is recorded so a model that keeps failing gets demoted, not hidden.
    • Every wait and every rung share one deadline. When the time left cannot cover the next rung, the ladder stops early with LLM_UNAVAILABLE and retryable=true.
    • When every rung is out of quota, the ladder says so at once and sends no request.

    Porting ai-ladder to the server

    What to keep, what to change

    Keep: a fixed order from the best model down; skipping rungs known to be out; reading retry-after, retryDelay and the PerDay marker in a 429; Gemini's daily quota resetting at midnight Pacific (15:00 Vietnam time in winter); backing off further when the provider gives no time; and never swapping a model pinned by hand. SEA-HELM also confirms that Gemini 3.8 Flash and 3.6 Flash on the ai-ladder are among the best at Vietnamese.
    Drop the Mistral rung: Mistral Medium 3.5 scores only 68.82 in Vietnamese and 46.55 on culture. Mistral Large is not on SEA-HELM, so there is no evidence that rung is good enough for Vietnamese legal questions.
    Where quota lives: move from localStorage to a locked JSON file (e.g. data/.llm_quota.json) shared by every worker. Key it by sha256(key)[:8] instead of the key's last 6 characters.
    Never cut the context: ai-ladder trims text to fit (the fit function). In a legal text, cutting a clause changes the meaning. So when the config loads, reject any rung whose context window is smaller than rung 1's largest prompt.
    A 413 does not lock the model: ai-ladder locks a model for 10 minutes on a 413, but a 413 means this request is too large, not that the model is broken. Skip the rung for this request only.
    A 400 must not silently drop thinking: ai-ladder resends without reasoning_effort, falling back to the model default, which may be low. On the server this must count as a config error, caught by a startup smoke test, not a quiet change of behaviour.
    Wait on a 429 inside the deadline: ai-ladder may wait up to 20 seconds. Here, wait only when the time left still covers that rung's latency.
    Team decision needed: llm-proposal.md says "do not switch provider on error", and settings.validate() requires LLM_MAX_RETRIES=0. The ladder changes the Week 1 decision, so update the doc and add an on/off switch: an empty LLM_LADDER runs the old one-model way.
