    Key points

    Simulated with the proposed rules

    Key points

    • Keep Team 3's spec: a bad output is not retried, not even on another rung. It is counted so the model can be demoted, not hidden.
    • Every wait and every rung draws on the same deadline. When there is no longer time, stop early with LLM_UNAVAILABLE, retryable=true.
    • When every rung is out, say so at once and send no request.

    Porting ai-ladder to the server

    What to keep, what to change

    Keep: fixed order from best down, skip rungs known to be out, read retry-after/retryDelay/PerDay, Gemini's daily quota ends at midnight Pacific (15:00 Vietnam time in winter), back off further when the provider gives no time, and never swap a model pinned by hand.
    Where quota lives: localStorage → a locked JSON file (e.g. data/.llm_quota.json) shared by all workers. Key it by sha256(key)[:8] instead of the key's last 6 characters.
    Never cut the context: ai-ladder trims text to fit (fit). In law, cutting a clause changes its meaning. When the config loads, reject any rung whose context window is smaller than rung 1's largest prompt.
    413 does not lock the model: ai-ladder locks a model for 10 minutes on 413, but 413 means this request is too large, not that the model is down. Skip the rung for this request only.
    A 400 must not silently drop thinking: ai-ladder resends without reasoning_effort, falling back to the model default, which may be low. On the server this is a config error: catch it in a startup smoke test instead of changing behaviour quietly.
    Wait on 429 inside the deadline: ai-ladder waits up to 20 s. Here, wait only when the time left still covers that rung's latency.
    Team decision needed: llm-proposal.md says "do not switch provider on error", and settings.validate() requires LLM_MAX_RETRIES=0. The ladder changes the Week 1 decision, so update the doc and add an on/off switch (empty LLM_LADDER = the old one-model way).
